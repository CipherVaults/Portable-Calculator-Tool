## 3. Coding lessons

- A bare `cargo build` of a wasm32 cdylib embeds absolute source paths of dependencies (the cargo home, so the user name) in panic-location strings, and the bytes then differ between machines. `trim-paths` is unstable on Cargo 1.99.1; `scripts/build-wasm.mjs` remaps the cargo home and the repo through `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUSTFLAGS` (or `CARGO_ENCODED_RUSTFLAGS` when a path has spaces) and fails if any local path remains.
- Remapped paths still keep the host's separators (`/cargo\registry\…` on Windows), so engine.wasm is reproducible per OS, not across Windows and Linux. CI builds the published one on Linux.
- `tauri::generate_context!` needs `frontendDist` to exist at compile time; `src-tauri` points at `dist/desktop`, so build it (`build-web.mjs --desktop-only`) before compiling the desktop app.
- `#![forbid(unsafe_code)]` works on the Tauri binary crate (the macros generate no `unsafe`).
- Template substitution must be a single pass over the template only; a later global edit (such as removing blank lines) would change inlined CSS/JS after its CSP hash was computed.
- `clippy::assertions_on_constants` fires on `assert!` over consts in tests; use `const { assert!(…) }`.
- Headless Chromium on Windows keeps a minimum window width (about 500 px): `--window-size=375,…` screenshots are a crop of a wider layout and look like overflow. Check phone widths with device emulation (browser pane mobile preset), not the headless window size.
- A "build twice" check that only cleans the final package reuses every dependency artefact; build the second copy in its own empty target dir.
- Never ship from a path another command also writes: a bare `cargo build` overwrote the remapped engine at cargo's output path, and the web build shipped it. The verified build now gets its own path, and every consumer re-scans for local paths.
- A regex that strips `//` comments also strips the rest of a line after `"a//"` or `"http://"`, hiding banned code. Scan raw text and keep banned words out of comments, and prove every rule with a mutant.
- When a lower layer refuses before the op lookup (the WASM input limit), the caller must restore the documented order of checks itself; here the loader asks about the op alone.

## 4. Spec deviations (M0)

- `crates/percent-core`: added `#![forbid(unsafe_code)]`, `ENGINE_VERSION` ("2.3.0") with an equality test, `license`/`publish` keys, and `[[example]] test = true` for `percent_bridge` (its existing framing tests now run). No behaviour change; its `.expect()` removal stays in M2c as planned.
- `date.*` op names drop date-core's `calc_` prefix (`date.days_between` … `date.validate_calendar`); the mapping is tested.
- `pcalc-api` error codes for percent errors: `zero_divisor` (original value, total, percent, cost, selling price, tax rate -100%), `negative_value` (bill, tip %), `invalid_people`; the message is percent-core's original English text.
- Op caps: every M0 op has the 64 KiB engine cap; the 256 KiB / 4.5 MiB / 8 MiB constants exist and attach to their ops in M3. `legacy.*` ops are not planned (owner clarification).
- `pcalc-wasm` is `crate-type = ["cdylib", "rlib"]` so its safe core is unit-tested natively.
- Ubuntu CI excludes the Tauri crate from clippy/tests (it needs WebKitGTK); the Windows job lints, tests and smoke-tests it.
- Icons are the Date Calculator's set as placeholders until a real icon exists.
- Desktop smoke has no clipboard round trip yet (no clipboard plugin until the history/copy work).
- percent-core's discount, markup, tax and tip `label` contains `<br>` and `pcalc-api` passes it through unchanged (percent-core output stays byte-identical; `copyText` has the newline form). Known item for M2c: the UI shows text only, so it uses the `*Text` fields or a split label, never HTML.
- The D-slice is safety-eval **slice D only**; slice A (parity) is `check-wasm.mjs`; slices B, C and E arrive with M2a/M2b, M3 and M9.
- Static rules are stricter than the plan text: banned names may not appear in comments either (raw-text scan).
